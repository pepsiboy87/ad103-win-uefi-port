# 我把 RTX 4080 被锁的一半算力解开了（Windows / Z390 老主板）

起因很简单：查资料时发现 4080 的 FP16（FP32 累加）在消费卡上只有半速，而同一颗 AD103 的专业卡是满速。参数表里明明白白写着 1/2 rate。

社区已经有现成方法（TOTORONG / JustAResearcher / Zagitta 那条线），但在 **Windows + 零售 4080 16G + 2018 年的 Z390 老主板** 这个组合上，我搜不到公开的成功案例。周末就自己试了。

## 结果

| 负载（torch，原生 Windows，4096³，3 次中位数） | 解锁前 | 解锁后 | 变化 |
|---|---:|---:|---:|
| FP32 GEMM | 35.49 TFLOPS | 35.48 TFLOPS | — |
| **FP16 → FP32 累加** | **91.93** | **174.35** | **+89.7%** |
| **BF16 → FP32 累加** | **91.94** | **176.20** | **+91.6%** |

第三次冷启动复测：FP16 **175.17**、BF16 **174.68**，与首次一致。

选择器状态（运行日志）：

```
冷态：FEAT_PLM=0xffffff8f  SS0=0x56114027  SS1=0x0  WPR2_HI=0
之后：SS0=0x88888888       SS1=0x8        matched=1（两者）  并存活于 PCIe FLR
```

冷启动三次都复现：每次开机 SS0 复位到 `0x54110026`，再被写入 `0x88888888`，过了 PCIe FLR 还在。不是心理作用。

## 踩的坑主要在"所有权"，不在参数

1. **固件开机就把显卡占住**（BY_DRIVER 计数为 1），"检查无占用"的准入永远过不去
2. **`DisconnectController` 传 NULL 会把 PCI 总线绑定一起拆掉**，固件当场挂死；正确做法是只断持有者，且在 `TPL_NOTIFY` 下执行
3. **断开后句柄被销毁**，得按 BDF 重新枚举 `PciIo` 才能继续
4. 前面都过了，**引擎还会返回 `0xbadf5620`**（访问无效的哨兵值）

一共上了 24 次电，前 14 次全败。

## 一个反直觉的结论

**这东西对量化推理（FP8 / INT8 / GGUF）基本没用。**

我那个 19.9G 的视频模型在 16G 卡上跑，解锁前后都在 312 秒左右——瓶颈是显存换入换出，不是算力。这些选择器管不到 fp8 那条路径，而且模型根本装不进显存，循环是传输受限而不是发射受限。

顺带纠正我自己之前的一个错误：我一度以为某次 146 秒的提速来自某个 turbo LoRA，后来查日志发现那个 LoRA 的键名缺 `diffusion_model.` 前缀，根本没加载成功——146 秒是"8 步、不带 LoRA"的成绩。所以真正让出片变快的，是步数，不是解锁，也不是那个 LoRA。

## 一点感想

解锁这件事本身挺爽，但它教会我的反而是另一件事：**先找瓶颈，再折腾**。我折腾了一圈固件，最后真正提速的是把 20 步改成 8 步。硬件参数上的"一半"很诱人，但你的工作流可能压根不跑在那条路径上。
